# 07 · RAG 与智能响应

**状态：** Accepted  
**版本：** v0.1

## 1. 目标与非目标

**目标**

- 缩短重复问题的首次有效反馈时间  
- 把社区优质内容沉淀为可检索知识  
- 所有 AI 输出可追溯引用，并可关闭  

**非目标**

- 成为「全学科无所不知」的聊天机器人  
- 自动以 AI 身份正式回帖（默认关闭）  
- MVP 自托管大模型  

## 2. 流水线总览

```mermaid
flowchart LR
    A[帖子文本+结构化字段] --> B[清洗与分段]
    B --> C[混合检索]
    C --> D[重排序]
    D --> E[组 Prompt + 引用]
    E --> F[LLM 生成草稿]
    F --> G[安全过滤与展示]
```

## 3. 语料来源（分阶段）

| 阶段 | 来源 | 闸门 |
|------|------|------|
| MVP | 种子 FAQ、公开软件文档摘要（遵守许可） | 人工整理 |
| MVP+ | 论坛已采纳回答、高赞帖 | 版主审核 `approved` |
| 后期 | 用户贡献笔记、工具卡正文 | 许可字段 + 审核 |

**禁止入库**：疑似侵权全文、未授权付费文献正文、含隐私/密钥的日志未脱敏内容。

## 4. 分块策略

| 内容类型 | 建议 |
|----------|------|
| 问答对 | 问+采纳答作为一块；过长则答分段并共享 metadata |
| 长文档 | 512–1024 tokens，重叠 10–15% |
| 报错类 | 保留 `error_log` 关键片段独立一块，metadata 带 `software_name` |

Metadata **必须**尽量包含：`software_name` `category` `tags` `source_url` `license`。

## 5. 检索策略

### 5.1 MVP（实用够用）

1. 向量检索 TopK（如 20）  
2. 关键词/BM25 或 Postgres `tsvector` TopK  
3. 简单融合（RRF）  
4. 按 `software_name` 等 metadata 软过滤  
5. 截断至上下文窗口预算  

### 5.2 进阶（成长期）

- Cross-Encoder 重排  
- Query rewriting（对报错帖提取软件名+错误类型）  
- 多路召回：工具卡 / FAQ / 帖子分索引  

## 6. Prompt 契约

系统提示必须包含：

1. 你是科研通助手，回答仅供参考  
2. 优先依据给定检索片段；无依据时明确说不知道  
3. 给出可点击的引用列表  
4. 涉及文献获取时只提供合法途径建议  
5. 不输出可执行的破坏性命令；排错命令需可逆说明  

用户消息模板：标题、正文摘要、结构化字段、检索片段列表。

## 7. 展示与产品安全

| 规则 | 级别 |
|------|------|
| UI 固定文案：「AI 建议，请人工核实」 | 必须 |
| 总开关 `AI_SUGGEST_ENABLED` | 必须 |
| 失败/超时不影响发帖成功 | 必须 |
| 默认不自动发帖 | 必须 |
| 记录 `model`/`latency`/`suggestion_id` 便于审计 | 必须 |

## 8. 评测集

维护 `services/rag/eval/`（代码阶段）：

- 50–100 条真实或脱敏问答  
- 指标：引用是否相关、是否胡编、延迟 P95、空答率  
- 改 Prompt / 分块 / 模型前跑回归  

发布门槛（建议）：胡编率人工抽检不可明显高于基线；P95 < 配置超时。

## 9. 成本控制

- 相似帖可仅向量、不调 LLM  
- 草稿生成可对短帖/低质帖跳过  
- 缓存：相同 `content_hash` 短 TTL  
- 选择性价比 API；密钥仅存服务端  

## 10. 与论坛集成方式

| 方式 | 适用 |
|------|------|
| 论坛插件 + 服务端 API | Discourse/NodeBB 均推荐 |
| 门户侧预填后跳转发帖 | 次优 |
| 爬取页面 | 禁止 |

## 11. 脱敏

入库与送入 LLM 前：

- 邮箱、手机号、IP、绝对路径中的用户名  
- `API_KEY`、`TOKEN`、`PASSWORD` 模式  
- 过长二进制/Base64 附件内容
