# 14 · 架构决策记录（ADR）

**状态：** Accepted（目录）  
**版本：** v0.1

ADR 用于记录「当时为什么这样选」。格式统一，拍板后只追加，不删改历史；若推翻则新建 ADR 并标记旧条 `Superseded`。

## ADR 模板

```markdown
# ADR-XXX: 标题

- 状态: Proposed | Accepted | Superseded by ADR-YYY
- 日期: YYYY-MM-DD
- 决策人:

## 背景

## 决策

## 后果

## 备选方案
```

## ADR-001: 论坛引擎选型

- 状态: **Accepted**  
- 日期: 2026-08-25  
- 决策人: 项目负责人  

### 背景

科研通 MVP 以社区为核心，需在 Discourse 与 NodeBB 间选择，避免自研论坛。算力与运维成本需可控，并与 TypeScript 自研服务栈对齐。

### 决策

采用 **NodeBB** 作为论坛引擎。

### 后果

- 建议起步规格 **2C4G**（低于 Discourse 的 8G 建议）  
- 插件与 Webhook 按 NodeBB 上游实现；配置覆写放在 `forum/nodebb/`  
- 12 个月内原则上不更换引擎；若更换须新 ADR 并标记本条 Superseded  

### 备选方案

- Discourse：运营/SEO 更强，但内存占用高——否决（当前资源与同栈优先级）  
- Flarum、自研：否决（生态或成本不适合 MVP）  

---

## ADR-002: MVP 优先论坛而非独立 RAG 机器人

- 状态: **Accepted**  
- 日期: 2026-08-24  

### 背景

存在两条启动路径：先做文献互助论坛，或先做科研问答机器人。

### 决策

采用 **论坛优先 + 发帖场景轻量 RAG 初答**；不把独立聊天机器人作为 MVP。

### 后果

- 内容资产与 SEO 起步更实  
- RAG 依赖种子帖与审核入库，冷启动需运营  
- AI 以插件/侧栏建议形态出现  

### 备选方案

纯 RAG 机器人：否决（缺自有语料、难留存、与贡献激励冲突）。

## ADR-003: LLM 使用外部 API，MVP 不自托管大模型

- 状态: **Accepted**  
- 日期: 2026-08-25  

### 背景

需控制成本与运维复杂度，同时验证初答价值。

### 决策

生成走外部 LLM API；Embedding 可用 API 或 CPU 小模型；不采购 GPU。

### 后果

有按量费用与供应商依赖；通过预算告警与开关控制风险。

### 备选方案

自托管 7B+：推迟至有明确 ROI。

## ADR-004: 分析与业务库权威分离，论坛库不直写

- 状态: **Accepted**  
- 日期: 2026-08-25  

### 背景

多子系统易出现跨库脏写。

### 决策

帖子权威在论坛；积分/工具/Job 在自研 PG；集成仅 API/Webhook/官方插件。

### 后果

有一定同步延迟与工程量；换论坛版本更安全。

## ADR-005: 部署形态 —— 国内 VPS 为主，Zeabur 为辅

- 状态: **Accepted**  
- 日期: 2026-08-25  

### 背景

需兼顾备案/延迟与快速部署。

### 决策

## ADR-006: 主仓库采用 Apache License 2.0

- 状态: **Accepted**  
- 日期: 2026-08-25  
- 决策人: 项目负责人  

### 背景

科研通以开源共享为宗旨，需选定适合大型协作、含专利授权条款的 OSI 许可。计划草案曾称 ADR-003，因编号已被「外部 LLM」占用，故记为 ADR-006。

### 决策

主仓库与默认贡献许可为 **Apache-2.0**（见根目录 `LICENSE` / `NOTICE`）。

### 后果

- 贡献默认同许可（见 `CONTRIBUTING.md`）  
- NodeBB 等上游仍遵循其各自许可证  
- 工具卡需声明自身 `license` 字段  

### 备选方案

MIT：更短但专利条款弱——未选。GPL：对插件生态传染性强——未选。

## ADR-007: Monorepo 与分层贡献模型

- 状态: **Accepted**  
- 日期: 2026-08-25  
- 决策人: 项目负责人  

### 背景

大型长期项目需单一协作入口，同时让「不会写核心代码」的人也能贡献。计划草案曾称 ADR-004，因编号已被「库权威分离」占用，故记为 ADR-007。

### 决策

1. 采用 **pnpm workspace + Python services** 的 Monorepo（`apps/` `services/` `packages/` `catalog/` `forum/` `infra/`）  
2. 分层贡献：论坛回答 → `catalog/tools` YAML → `docs/` → 代码 PR  
3. 本地最小依赖：`infra/docker-compose.dev.yml`（Postgres/Redis）+ `scripts/smoke.sh` + CI  

### 后果

- 贡献路径写在 `CONTRIBUTING.md` / `docs/12-contribution.md`  
- 子系统可独立扩缩，但版本与契约在仓库内对齐  
- MVP 仍禁止引入 K8s / 自研论坛引擎  

### 备选方案

多仓库拆分：过早增加协作成本——否决。纯文档仓库无骨架：无法验证稳定性——否决。

## ADR-008: 校园邮箱会员、JSON 用户库与设备上限

- 状态: **Accepted**
- 日期: 2026-10-23
- 决策人: 项目负责人

### 背景

门户与管理端将作为两个 Zeabur 服务部署，磁盘不共享。需要校园身份门槛、一周试用、永久会员（文案 ¥19.9，本阶段不接支付），以及限制账号共享。浏览器拿不到 MAC 地址。

### 决策

1. 注册仅接受 `.edu.cn` / `.edu` 校园邮箱；验证后开始 7 天试用。
2. 用户数据由门户写入 `DATA_DIR/users.json`；管理端用共享 `INTERNAL_API_SECRET` 调用门户 `/api/internal/users` 发放/收回永久会员、踢设备。
3. 设备绑定使用客户端生成的 UUID（localStorage + cookie），每账号最多 2 台；**禁止采集 MAC**。
4. 文献关系网与发求助帖要求 `isEntitled`（试用未过期或永久）。图谱数据只用 OpenAlex 公开 API，交互参考「种子→邻域」，不复制商业产品界面。
5. 支付网关与 SMTP 本阶段不做；验证码可 `EMAIL_DEV_ECHO` 打日志，终身由管理员手工发放。

### 后果

- 双服务必须配置同一内部密钥；用户文件需挂在门户持久卷，并 gitignore `data/`。
- 设备限制可被清站点数据绕过，只作轻度防共享。
- 后续若接支付或 Postgres，新 ADR 标记本条部分字段 Superseded。

### 备选方案

- MAC 绑定：浏览器不可得且隐私风险——否决。
- 两服务各写一份用户文件：状态必然分叉——否决。
- 本阶段直接上微信/支付宝：范围过大——推迟。

## ADR-009 · 科研广场与独立组学分析入口（Accepted，2026-11-05）

根据用户最新产品要求，首页增加居中科研动态，拆分科研工具与组学分析，文献获取求助从 GitHub Issue 过渡为站内帖子/响应/采纳。公开浏览，普通登录用户可参与，不与会员计算权限绑定。JSON 存储沿用单机阶段约束，多实例写入前需迁移数据库。详见 [28](./28-research-commons.md)。

## ADR-010 · 公共专属角色的 Harness SDK 适配层（Accepted，2026-11-05）

用户要求使用已部署的 DeepSeek Harness 能力打造个人角色。新增内部令牌保护的 SDK bridge 与独立运行数据卷，固定 0.2.1-rc.5；不把运维 Web UI、共享会话、密钥或 shell 工具开放给公共用户。按用户/角色隔离，门户仍执行权限与额度检查。详见 [28](./28-research-commons.md)。

## ADR-011 · NCBI 本机浏览器与 native host 自动化（Accepted，2026-11-05）

用户已明确要求扩展原 no_browser_automation 范围。允许受限自动化运行于用户本机 Chrome 扩展，使用已登录 NCBI 会话获取上传配置并保管本机私钥，通过 Native Messaging 调用用户级本机助手。保持原始测序数据不经门户、云端不持 NCBI 密码/cookies/私钥的边界。系统安装许可、未知网页、敏感数据授权与最终提交保留用户核对；当前开发预览尚未实现全部网页步骤自动推进。详见 [29](./29-ncbi-automation.md)。

## ADR-012 · PostgreSQL 身份主库、Redis 唤醒与 S3 对象分层（Accepted，2026-11-05）

按用户授权先迁移账号、校园验证、会员、设备和会话，后续逐模块迁移。身份操作使用独立低权限数据库登录，模块数据采用 owner RLS 和复合外键。数据库事务 outbox/任务租约保证任务可恢复，Redis 不作为业务权威数据。S3 兼容对象层使用私有版本桶；知识来源和训练集保留许可、授权版本及撤回条件，默认不进入 RAG/训练。显式切换、迁移前备份、逐字段核验与最新数据回滚导出为上线要求。详见 [30](./30-unified-storage.md)。本决策替代 ADR-008 中“用户 JSON 作为长期主库”的部分；其他 JSON 模块待后续迁移。

## ADR-013 · 统一组学运行契约与可审核科研资源目录（Accepted，2026-11-05）

新增版本化方法注册表与共享 CPU 镜像，以固定白名单、私有对象输入和 PostgreSQL 租约任务执行 GWAS/BSA 基线。前期研究适配器和 CausalBSA 规范保留证据分级，完成本站验证后才开放。资源目录使用 PostgreSQL 版本审核与用户归属隔离，所有社区补充须审核公开、退回可修订重提。植物基因组导航独立于工具目录。详见 [31](./31-omics-and-resource-atlas.md)。

## ADR-014：公共门户以连续对话作为唯一操作入口（2026-11-05）

用户明确要求转型为对话操作网站。采用根级连续会话、内容展示空间和允许列表命令规划，移除公共导航与按钮式业务流程；仅文件操作、下载和对话控件保留直接交互。模型只规划，认证、参数校验、私有下载与执行权限仍由业务 API 负责。公开写入先完整预览，再使用用户绑定的短期签名凭据和受 RLS 保护的执行台账确认，支持重试去重。文件仅在内存中随软跳转保留；认证秘密不进入模型。后台审核维持独立管理界面。实现和边界见[对话式门户](32-conversation-native-portal.md)。

## ADR-015：Harness 负责意图规划，业务服务提供执行回执

复用官方 Harness SDK，以隔离且不持久化的规划轮处理非确定性表达；专属角色仍保留各自会话。所有命令由门户允许列表解释，业务权限、参数校验与签名确认仍由服务端执行。聊天反馈源自业务响应和工作进程记录，不以模型表述代替执行结果。任务监控归属全局对话层；详情见[对话闭环](33-conversation-execution-loop.md)。

## ADR-016 · 区分任务记忆与用户偏好

### 已实现的任务记忆

- PostgreSQL 按账号与任务保存对话、方法、参数、附件用途和任务编号。任务版本用于防止另一设备的旧快照覆盖新进度。已有快照可继续读取，新字段可缺省。
- 文件名引用记录为待提供文件，已读附件记录为可处理输入。重新打开任务时，原浏览器从 IndexedDB 恢复附件。其他设备可恢复任务背景，需重新选入附件才能计算。
- 模型按本次对话提供的任务事实和近期消息规划。识别附件时只发送允许列表中的字段类型、列数和数值统计。原始数据、样本列名、路径和认证秘密不进入文件识别请求。模型分类不能启动分析或传输。

### 待实现的用户记忆

- 新建归账号所有的偏好记录。仅保存用户明确要求跨任务记住的设置，例如常用参考基因组版本、报告语言。实验分组、样本、输入、结果和 NCBI 配置留在原任务。
- 每条偏好记录保存键、值、确认时间及来源，提供查看、修改和忘记入口。加载时由服务端按当前会话查找，供新任务提出默认建议。优先级为本次明确指令、当前任务已保存配置、用户偏好、系统默认。物种、参考版本或统计方法有冲突时由用户确认。
- 偏好与任务记录分别实施账号隔离。用户关闭或删除偏好后，新规划不再使用它。未经独立授权，不将用户记忆用于共享检索或训练。上线验证覆盖同账号跨任务、不同账号隔离、历史恢复和删除后的读取行为。

## ADR-017 · NCBI 免安装暂存先独立上线

浏览器经同源认证 API 上传 FASTQ 分片，PostgreSQL 记录任务归属、配额、有效期和分片校验值。生产先使用与常规备份分离的私有暂存卷，续传时按既有分片校验原文件。暂存完成与 NCBI 接收是不同状态。NCBI 云端导入等待受支持的存储和测试提交授权，详见 [NCBI 上传设计](29-ncbi-automation.md)。
