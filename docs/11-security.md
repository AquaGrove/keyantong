# 11 · 安全与合规

**状态：** Accepted  
**版本：** v0.1

## 1. 安全原则

1. 最小权限  
2. 默认拒绝（上传、执行、入库）  
3. 纵深防御（WAF/限流/鉴权/审计）  
4. 假设 UGC 全不可信  
5. 合规优先于增长  

## 2. 认证与授权

| 阶段 | 方案 |
|------|------|
| MVP | 论坛账号体系为主；自研 API 校验论坛签发 token 或服务端 session 桥接 |
| 成长期 | OIDC/SSO，门户与论坛统一登录 |
| 永远 | 管理接口独立强鉴权；Webhook HMAC |

角色：`user` < `contributor` < `mod` < `admin`。

## 3. 内容安全

### 3.1 社区规约必须覆盖

- 禁止非法文献分发与破解软件分享  
- 禁止人身攻击、学术不端教唆  
- 禁止恶意代码、挖矿脚本、未说明的可执行附件  
- 鼓励最小复现、脱敏日志  

### 3.2 处置流程

举报 → 版主 24–72h 处理 → 下架/封禁 → 留存审计日志。  
重大合规（版权律师函等）→ 负责人立即处理。

## 4. 文献相关合规（硬约束）

| 允许 | 禁止 |
|------|------|
| 讨论检索策略、馆际、作者主页、OA、预印本 | 上传/外链盗版 PDF 作为站内资源 |
| 分享 DOI、PMID、合法库入口 | 组织批量盗爬付费库 |
| 解读公开摘要（注意引用） | 把付费全文粘贴入库给 AI |

AI Prompt **必须**拒绝协助非法获取全文。

## 5. 上传与执行安全

- 附件类型白名单；可执行文件默认禁  
- 病毒扫描（成长期）  
- 分析 Worker：**无特权容器**、只读根、网络默认关、资源限额、超时杀掉  
- **禁止**提供任意用户 Dockerfile 免审上线  

## 6. 隐私

- 日志脱敏（见 RAG 文档）  
- 最小化采集邮箱/手机  
- 对外展示默认昵称  
- 用户可申请注销（流程成长期完善）  
- 隐私政策与用户协议上线前必须有可访问页面  

## 7. 密钥与供应链

- 密钥轮换流程；泄漏即轮换  
- 依赖锁定与 CI 审计（`npm audit` / `pip` 工具）  
- 镜像来自可信仓库；贡献镜像需扫描  

## 8. 安全响应

发现漏洞：

1. 不要公开 PoC 到论坛  
2. 邮件/私信负责人  
3. 修复后可选致谢
