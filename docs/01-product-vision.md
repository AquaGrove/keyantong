# 01 · 产品愿景与问题定义

**状态：** Accepted  
**版本：** v0.1

## 1. 愿景

建设一个面向科研人员的综合性平台：**开源共享、人人可贡献**；社区互助可沉淀、工具经验可复用、基础分析可触达、知识响应可智能化。

科研通不是「另一个全能生信平台」，而是：

> 以开源仓库与论坛为公共底座，以积分与声誉激励贡献，以 RAG 缩短首次响应时间，以可扩展工具与分析微服务降低跨平台切换成本——**任何人都可按规范出力，无需拿到核心权限也能扩展生态**。

### 1.1 开源共享宗旨（最高优先级文化约束）

| 要求 | 说明 |
|------|------|
| MUST | 主仓库以 Apache-2.0 开源；贡献路径公开文档化 |
| MUST | 提供低门槛贡献（回答、工具卡 YAML）与代码贡献分层 |
| MUST NOT | 将关键能力闭源化到无法复现社区流程 |
| SHOULD | 重大决策走 ADR；破坏性变更可讨论、可回滚 |

## 2. 现存问题（Problem）

### 2.1 工具与信息碎片化

科研人员在文献获取策略、软件环境依赖排错、数据分析之间，需要在多个站点、群聊、文档间反复切换；答案分散、难检索、难复现。

### 2.2 互助响应慢、个性化难匹配

传统论坛/群聊对「特定报错日志」「特定分析流程」「特定物种或数据格式」响应慢；新手问题重复出现，资深用户重复回答。

### 2.3 在线分析工具领域割裂

部分在线工具只服务狭窄领域或单一流程，跨领域、跨物种的通用能力弱；用户仍需自建环境。

### 2.4 信任、质量与激励不足（补充）

- 错误答案与过期链接难以识别  
- 愿意深度回答的人缺少可见回报  
- 经验无法结构化沉淀为可检索资产  

## 3. 项目现有基础（Foundation）

| 基础 | 对项目的意义 |
|------|----------------|
| 独立站与完整 Web 部署、域名配置经验 | 可快速落地 MVP 与备案主站 |
| 大语言模型与高级 RAG（分块、检索策略）认知 | 智能初答与知识库具备差异化可能 |
| 复杂系统规划能力（预处理→工具→流程闭环） | 适合模块化、API 优先架构 |

## 4. 拟解决问题（Goals）

| 优先级 | 目标 | 对应能力 |
|--------|------|----------|
| P0 | 降低求助无人答、答了找不到的成本 | 分类论坛 + 搜索 + 采纳 |
| P1 | 缩短重复问题首次响应时间 | 相似帖 + RAG 初答 |
| P2 | 沉淀软件安装与环境排错经验 | 软件模块 + 模板 |
| P3 | 提供少量通用在线分析能力 | 分析微服务 |
| P4 | 让外部贡献者可扩展生态 | 插件/贡献包规范 |

## 5. 产品边界

### 5.1 我们做什么

- 文献：**求助、荐源、检索策略、合规获取路径讨论**
- 软件：**安装、依赖、版本兼容、工作流与排错**
- 分析：**通用、可组合的轻量工具**（格式转换、基础 QC、可视化等）
- AI：**辅助响应与知识沉淀**，明确标注为建议而非权威

### 5.2 我们不做什么（Non-Goals）

| 禁止方向 | 原因 |
|----------|------|
| 盗版文献/付费全文非法分发 | 法律与平台风险 |
| 替代 Galaxy / HPC 全功能平台 | 工程量与运维成本失控 |
| 以聊天机器人替代社区 | 无自有语料难留存，且削弱贡献激励 |
| MVP 阶段自托管大模型与 GPU 集群 | 成本高、非验证重点 |
| 复杂金融级积分兑换现金 | 合规与运营复杂度过高（早期） |

## 6. 目标用户

| 角色 | 诉求 | 成功表现 |
|------|------|----------|
| 研究生 / 青年科研 | 快速解决报错与文献策略 | 24h 内获得可用答案 |
| 实验室技术骨干 | 分享环境与流程，建立声誉 | 答案被采纳、工具被引用 |
| 工具作者 | 发布可复现环境与小工具 | 贡献包通过审核上线 |
| 站务 / 版主 | 治理质量与合规 | 清晰审核与封禁工具 |

## 7. 差异化对照

| 类型 | 代表 | 科研通差异 |
|------|------|------------|
| 文献灰产站 | — | **合规互助**，不做非法分发 |
| 通用问答 | Stack Overflow | 科研场景标签与结构化字段更强 |
| 生信社区 | 各类论坛/群 | 知识可入库 + AI 初答 + 工具扩展 |
| 分析平台 | Galaxy 等 | 只做通用轻量工具，不正面替代 |

## 8. 成功指标（产品层）

见 [MVP 与路线图](./10-roadmap-mvp.md) 中的量化验收；战略级指标包括：

- 社区是否产生可持续的高质量采纳内容  
- RAG 是否降低首次有效响应时间  
- **外部贡献者是否能在不改核心代码的情况下扩展工具卡 / 分析包**  
- 开源仓库是否具备可运行骨架、CI 与清晰贡献指南（冷启动工程健康度）  

## 9. 规划模式总结

```text
现存问题（碎片化 / 慢响应 / 工具割裂 / 激励弱）
        ↓
已有基础（部署经验 / RAG 认知 / 系统规划）
        ↓
拟解决问题（论坛 P0 → RAG P1 → 软件 P2 → 分析 P3 → 贡献 P4）
```
