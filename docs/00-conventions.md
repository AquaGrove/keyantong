## 2. 术语表

| 术语 | 含义 |
|------|------|
| 门户（Portal） | 品牌首页、导航、热门内容聚合，非论坛本体 |
| 论坛（Forum） | 基于 **NodeBB** 的社区系统 |
| 需求帖 | 文献求助、软件排错、流程咨询等结构化发帖 |
| 采纳 | 提问者将某回复标为最佳答案，触发积分结算 |
| 智能初答 | 发帖后由 RAG 生成的「AI 建议」草稿，非最终权威答案 |
| 知识入库 | 高赞/已采纳内容经审核进入向量知识库 |
| 工具卡 | 软件模块中的一条软件/环境/脚本元数据 |
| 分析作业（Job） | 在线分析平台的一次异步计算任务 |
| 贡献包 | 符合规范的 Docker/脚本/工作流提交物 |
| MVP | 最小可行性产品，见 `10-roadmap-mvp.md` |

## 3. 文档写法约定

- 使用简体中文为主；接口字段、代码标识用英文
- 配置示例中的密钥一律用占位符：`${SECRET}` / `changeme`
- 架构图优先 Mermaid，便于版本管理
- 「必须 / 禁止 / 建议」语义对齐 RFC 2119 精神：
  - **必须（MUST）**：违反即不合规
  - **禁止（MUST NOT）**
  - **建议（SHOULD）**：默认遵循，偏离需说明

## 5. 版本策略（代码阶段生效）

- 文档版本：`docs` 目录内 `vMAJOR.MINOR`
- 服务 API：语义化版本，破坏性变更升 MAJOR
- 论坛上游：锁定小版本，升级走独立变更窗口

## 6. 决策优先级

出现冲突时按下列顺序裁决：

1. 安全与合规（`11-security.md`）
2. 产品边界与非目标（`01-product-vision.md`）
3. 已 Accepted 的 ADR（`14-adr.md`）
4. 本索引下的专题文档
5. 口头讨论（事后必须落文档）
